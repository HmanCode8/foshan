# 佛山无人车系统\-后端功能与技术文档

## 一、项目概述

本项目为**佛山无人车系统**后端服务，基于 Spring Boot 生态开发，主要实现**用户账号体系管理**与**无人车相关业务数据管理**，包含账号注册、登录、密码找回、数据权限隔离等能力，支撑前端完成无人车业务全流程操作，保障系统账号安全与数据隔离。

## 三、核心功能模块

### （一）用户账号模块（核心基础模块）

该模块实现系统账号全生命周期管理，包含注册、登录、密码找回三大核心功能，全程对密码进行加密处理，保障账号安全。

#### 1\. 用户注册

- 校验用户名唯一性，禁止重复注册；

- 校验两次输入密码是否一致；

- 密码采用 BCrypt 算法加密后入库，不存储明文密码。

#### 2\. 用户登录

- 校验账号、加密密码是否匹配；

- 登录成功后生成 JWT 令牌返回前端；

- 令牌携带用户ID、用户名，用于后续接口身份识别。

#### 3\. 密码找回（邮件验证码模式）

- 发送验证码：校验账号与绑定邮箱是否匹配，生成6位数字验证码，通过 QQ 邮箱推送至用户邮箱，内存临时缓存验证码；

- 重置密码：校验入参完整性、验证码有效性、两次密码一致性，校验通过后重新加密密码并更新数据库。

### （二）无人车业务模块

实现无人车相关申请、数据管理功能，**基于用户ID做数据隔离**，不同用户仅可查看、操作自身创建的数据，包含区域、线、点三类无人车地理/轨迹相关申请管理。

#### 1\. 区域申请管理

- 新增：自动绑定当前登录用户ID，关联分段子表数据；

- 分页查询：按用户ID隔离数据，支持多条件筛选；

- 修改/删除：校验数据归属，仅数据创建人可操作，删除时级联清理子表数据。

#### 2\. 线申请管理

功能逻辑同区域申请，针对无人车路线轨迹数据做专项管理。

#### 3\. 点申请管理

功能逻辑同区域申请，针对无人车点位数据做专项管理。

## 六、认证与数据隔离设计

### 1\. 身份认证流程

- 用户登录成功，后端生成 JWT 令牌返回前端；

- 前端所有业务请求，在请求头携带 Token；

- 后端拦截器校验令牌有效性，解析出当前登录用户信息；

- 登录、注册、找回密码接口直接放行，其余接口必须校验令牌。

### 2\. 数据隔离规则

- 新增数据：自动填充当前登录用户ID，绑定数据归属人；

- 查询数据：SQL 强制拼接 `user\_id = 当前用户ID`，仅查询本人数据；

- 修改/删除：先校验数据所属用户与当前登录用户是否一致，不一致则拒绝操作。

## 七、关键技术实现细节

### 1\. 密码安全处理

- 前端传递密码，后端统一使用 **BCrypt** 加密算法二次加密入库；

- 登录、重置密码时，使用框架自带方法做加密比对，全程不出现明文密码。

### 2\. JWT 令牌

- 作用：实现服务端无状态认证，替代传统 Session；

- 功能：生成令牌、解析令牌、校验令牌是否过期/非法。

### 3\. 邮箱验证码功能

- 依托 `JavaMailSender` 对接 QQ 邮箱 SMTP 服务；

- 流程：校验账号邮箱 → 生成6位验证码 → 内存缓存验证码 → 邮件推送；

- 重置密码时校验验证码，使用后清空缓存。

### 4\. 分段数据处理

- 前端传入分段集合，后端循环绑定申请单ID、用户ID；

- 坐标数据转为 JSON 字符串存入数据库，查询时自动解析。

## 九、现存问题 \&amp; 后续优化方向

### 1\. 现有待优化点

- 验证码使用**内存 Map 缓存**，服务重启后验证码失效，无过期时间；

- 接口参数校验为硬编码判断，代码冗余，统一度低；

- 未做接口限流，找回密码接口存在被恶意刷取风险。

### 2\. 优化方案

- 替换内存缓存为 **Redis**，给验证码设置5分钟自动过期；

- 使用 `@Valid` \+ 实体类注解做统一参数校验，精简代码；

- 增加接口限流、防刷机制；

- 新增系统操作日志，记录用户登录、改密、数据操作行为。
